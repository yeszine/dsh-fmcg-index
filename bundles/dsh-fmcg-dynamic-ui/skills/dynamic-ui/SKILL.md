# dynamic-ui：内联可视化回答规范

本技能规定：在对话式回答中，何时以及如何用一段**自包含的 HTML/SVG 片段**替代大段文字，把关系、量级、流程或某个局部交互讲清楚。它是一种"回答增强"手段，不是建站或做报告的工具。

## 一、什么时候该画，什么时候不该画

### 适合内联可视化的场景

| 场景 | 典型诉求 | 推荐形态 |
|---|---|---|
| 数据与量级 | 趋势、占比、对比、分布、转化漏斗 | 折线/柱状/饼环/条形小图 |
| 架构与流程 | 模块关系、调用链、依赖、数据流向 | SVG 节点连线图、时序图 |
| 状态机与生命周期 | 状态集合、迁移条件、当前所处阶段 | 状态迁移图、阶段条 |
| 机制与原理 | 因果链、物理/抽象机制、分层结构 | 分层示意图、因果箭头图 |
| 对比与决策 | 方案取舍、选型矩阵、风险对照 | 对比卡片组、小型矩阵表 |
| 微交互与 mockup | 参数调节效果、表单草图、开关状态演示 | 带少量 JS 的局部控件 |

判断标准只有一条：**这张图是否有一个明确的视觉焦点**（推荐项、瓶颈、关键路径、最高值、阶段分界），且这个焦点用纯文字/Markdown 表达会明显更啰嗦。有就画，没有就不画。

### 不要内联可视化的场景

- 独立网站、完整应用、长报告、仪表盘、幻灯片——这些是大交付物，应走文件产出流程，而不是聊天内联片段。
- 一两句话就能说清的事实、单条命令、纯列表类内容——Markdown 扫读效率更高。
- 没有任何视觉焦点的"装饰性配图"——不解释任何问题的图不如不画。
- 需要精确录入/编辑数据的场景（表格编辑器、看板工具）——内联片段不是生产力工具。

## 二、输出形态与技术约束

### 单片段、自包含

- 一次输出一个独立片段：`<style>` 在前，内容 HTML/SVG 居中，`<script>`（仅当确需交互时）在最后。
- **不写** `<!DOCTYPE>`、`<html>`、`<head>`、`<body>` 等页面外壳，不假设宿主提供任何全局样式或脚本。
- 全部样式内联在片段的 `<style>` 中；选择器加统一前缀（如 `.dv-`）避免污染宿主页面。
- 不依赖宿主环境的 CSS 变量、字体或主题类——片段必须脱离宿主也能正常阅读。

### 外部依赖

- 默认零依赖：纯 CSS + SVG 能解决就不用库。
- 确需图表库（如 Chart.js）时，只从公共 CDN（jsdelivr、unpkg、cdnjs 等）加载，且必须提供**加载失败时的静态兜底内容**（例如预先渲染的 SVG 或表格），库加载成功后再增强。
- 禁止 `position: fixed`、全屏遮罩、嵌套滚动区域——片段必须像一段文字一样自然嵌入回答流。

### 深浅色适配

- 无法预知宿主主题是浅色还是深色，因此所有颜色走 CSS 变量，并提供深色覆盖：

```css
.dv-root {
  --text: #1f2329; --muted: #646a73; --surface: #ffffff;
  --border: #dee0e3; --brand: #34a853;
}
@media (prefers-color-scheme: dark) {
  .dv-root {
    --text: #e8eaed; --muted: #9aa0a6; --surface: #1f1f1f;
    --border: #3c4043; --brand: #4cc56b;
  }
}
```

- 文字、坐标轴、边框、卡片底色、连接线、标签全部引用变量，任何组件选择器和 SVG 属性里都不写死浅色专属色值。

## 三、视觉规范

### 配色

- **中性为主，强调色唯一**：底面、边框、连线用中性色；全图只用一个品牌色（默认绿色系）标记焦点或主系列。
- 多系列图表按固定次序取色（主色 → 次色 → 第三色 → 第四色），超过 4 个同类对象时归并为"Top N + 其他"，或改用表格/列表，不要上彩虹色。
- 红/黄/绿等语义色仅在数据字段本身就是状态、风险、健康度时使用；"成功/失败/警告"这类词出现在文本里不构成上色理由。
- 一个紧凑图里非中性的含义色不超过 2 种；超过就必须配图例。

### 排版与密度

- 字号阶梯固定：正文/标签 14px，注释/图例/元信息 12px，标题 16px 封顶，代码类数值 13px 等宽。不得低于 11px。
- 间距取 4 的倍数（4/8/12/16/20/24px），圆角默认 8px、卡片 12px、胶囊 999px，不发明临时数值。
- 文案密度：节点标签 2–5 个词，卡片标题 6–10 个词，连线标签 1–3 个词（显然可省则省）。句子式大小写，标识符/命令/路径用代码样式。
- 复杂度预算：1 个焦点、2–5 个主节点、最多 4 个并列选项或数据系列、1 种交互概念。超出就分组、拆成多个小图，或把细节放回文字。

### 图表纪律

- 图表片段只放图表本体、必要的轴/图例/标签/提示，**不在图内写结论、分析或建议**——结论属于周围的文字回答。
- 数据诚实：估算值标"估"，单位紧跟数字，口径一致地取整；来源模糊时宁可少画一个数。
- 不画地图，区域数据用条形/表格/矩阵表达。

## 四、SVG 作图硬规则

凡涉及 SVG 示意图（流程图、架构图、状态机、机制图），先在脑子里完成坐标规划，再动笔：

1. **画布**：推荐 `viewBox="0 0 720 H"`、`width="100%"`、`height="auto"`；四周安全边距 ≥40 单位；`H` 由最低元素加底部留白推出，不留大段无解释的空白，也不用负数坐标。
2. **文字占位估算**：14px 标签按每字符约 8px（英文）估算宽度，中文按字号全宽估算；代码、长标识符再加 30–50% 余量。节点宽 = 文字估算宽 + 两侧各 12px 内边距。**任何标签放不进去就先精简内容，禁止靠缩字号、裁剪、背景色遮盖来硬塞。**
3. **防重叠**：同行节点间留 ≥32 单位（流程步骤间 ≥60）；同列节点间 ≥28（之间有连线标签时 ≥56）。所有包围盒（含徽标、步骤号、图例）两两不得相交。
4. **连线**：路径一律 `fill="none"`；绕行无关节点，禁止穿过文字和节点；方向箭头用统一的 `marker-end` 小三角（`viewBox="0 0 8 8"`、`refX="7"`、`refY="4"`、`orient="auto"`），不要用装饰性曲线或超大楔形箭头；双向关系画两条带各自箭头的路径。
5. **连线标签**：放进带底色的小胶囊，胶囊与线保持 ≥8 单位间距，不压线；放不下就把说明挪到节点副标题或文字回答里。
6. **形状语义**：开始/结束用胶囊，判断节点用圆角菱形，普通步骤用圆角矩形；容器嵌套不超过 2–3 层，容器与子元素间留 ≥20px 内边距。
7. 无法满足以上任何一条时，改为分组、拆分、表格，或干脆用 Markdown 回答。

## 五、交互小控件规则

- 交互只做**局部行为**：切换、筛选、排序、步进、悬停查看、简单计算。不做出口跳转、路由、文件导流。
- 事件用 `addEventListener` 或根节点内事件委托绑定；所有 DOM 查询限定在片段根元素内，禁止全局选择器和内联 `onclick`。
- 动画用于澄清状态变化而非装饰：优先 `transform`/`opacity`，过渡 ≤120ms，首屏入场动画 120–220ms；持续性动效包在 `@media (prefers-reduced-motion: no-preference)` 里。
- 控件必须在脚本加载失败时仍可静态阅读（例如选项卡默认展开第一项、滑杆旁直接印出当前值）。

## 六、多个小图串联叙事

一个回答允许出现多个小图，但要讲成一条线：

- **一图一问**：每张图只回答一个明确的小问题（"钱花在哪"→"哪块在涨"→"涨的原因"），图与图之间用一两句文字承接，形成"总览 → 拆解 → 归因"的递进。
- **视觉一致**：同一回答内的所有片段共用同一套色板、字号阶梯、圆角和卡片样式，读者不应察觉风格切换。
- **焦点接力**：上一张图的焦点应当是下一张图的入口（上一张标出异常系列，下一张就拆这个系列），不要并列摆三张互不相干的图。
- **总量控制**：一次回答内联图不超过 3 张；信息仍装不下时，说明需要正式交付物，转入文件产出而非继续堆图。

## 七、决策流程（内部完成，不向用户播报）

1. 这个问题用 Markdown 能否同样清楚？能 → 不画。
2. 有没有唯一视觉焦点？没有 → 不画，或先帮用户收敛问题。
3. 属于哪类场景（数据 / 架构流程 / 对比决策 / 机制 / 微交互）？按对应形态选型。
4. 复杂度是否超预算？超 → 分组、拆图、或表格化。
5. 定稿后一次性输出完整片段；画图和布局的推演过程不出现在回答里，片段前后只留简短的文字引导。
