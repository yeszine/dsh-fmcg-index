# 研究报告

## 一、与父技能的关系

本文件完整继承 `research-guide` 中的约束：

- 来源可信度分层（S0–S3）、硬性约束、检索策略、交叉验证规则；
- 冲突处理：并列呈现分歧双方，不得随意取舍；
- 引用规范：正文内使用 `[来源:N]` 行内标注，文末附"信息来源"清单；
- 图表使用遵循父技能第四节。

以下内容是对父技能的**补充**，绝不与之冲突。

## 二、内容边界

报告是一份**独立可读的参考文档**，不依赖对话上下文也能看懂。

- 对用户的直接回答放在**对话回复**里，不放进报告正文。
- 可以把对话回复理解为"摘要"，报告理解为"完整论证"。
- 报告内只放研究发现、分析过程与证据。

## 三、格式规范

### 3.1 Markdown 约定

- 使用标准 GFM：标题、段落、列表、强调、链接、代码块、表格。
- 数学表达式如确需使用，用 `\( \)`（行内）和 `\[ \]`（独立成行），不使用 `$` 符号。
- 价格、百分比、日期等数字按普通文本处理，不要包进数学公式。

### 3.2 标题层级

- `#` 仅用于报告标题；`##` 用于主要章节；`###` 用于章节内的小节。
- 标题必须客观描述内容，不得使用反问、煽动或立场化的措辞。
- 不得跳级（例如 H1 直接接 H3）。

### 3.3 表格

- 涉及 2 个以上对象在同一属性上的对比时，优先使用表格。
- 表格超过 6–7 列时考虑拆分。
- 表格单元格内的数据同样要带来源标注。

## 四、报告结构

### 4.1 通用组件

| 组件 | 作用 |
| ---- | ---- |
| 标题（H1） | 清晰、描述性的报告题目 |
| 摘要 / 概览 | 核心发现的简要综合 |
| 主体章节（H2/H3） | 按主题、线索或论证组织 |
| 分析 / 讨论 | 解读、权衡、含义推演 |
| 结论 | 汇总发现并给出可执行的建议 |

### 4.2 分领域结构参考

| 领域 | 推荐结构 |
| ---- | -------- |
| 学术类 | 引言 → 文献综述 → 方法 → 分析 → 讨论 → 结论 |
| 投资 / 市场类 | 摘要 → 行业概览 → 竞争格局 → 财务分析 → 风险 → 结论 |
| 技术类 | 概览 → 架构 / 方法 → 分析 / 结果 → 讨论 |
| 政策 / 法律类 | 摘要 → 背景 → 利益相关方分析 → 证据梳理 → 影响 → 建议 |

结构服务于内容——简单问题不要硬套模板。

## 五、引用细则

### 5.1 何时必须引用

- 执行过实际检索；
- 报告中含有来自外部的事实性论断、统计数据、事件描述。

### 5.2 引用格式

- 行内：紧邻论断之后写 `[来源:N]`，多个来源连写如 `[来源:2][来源:5]`，中间不加空格。
- 表格：在"来源"列或数据单元格内标注。
- 文末：附"信息来源"清单，逐条列出编号、标题、链接。

### 5.3 引用纪律

- 只引用真实检索到的来源，禁止虚构编号。
- 每条实质性论断配 1–3 个引用，全文密度均匀。

## 六、写作原则

- **结论先行**：先给答案，再给论据。
- 段落以 3–8 句为宜；不使用第一人称（"我""我们"）或自指性表述。
- 天然成组的信息（选项、优缺点、步骤、建议）用列表；需要逻辑推进的论证用连贯段落。
- 篇幅匹配问题复杂度；同一信息不换个说法重复。
- 先介绍概念再展开使用；章节过渡要显式（"在此基础上……""与之相对……"）。
- 分析重于复述：解释因果、权衡取舍、指出"所以呢"。
- 来源冲突时：陈述分歧 → 评估各方来源质量 → 给出取舍理由。
- 始终对准用户的核心问题；预判后续追问并提前覆盖。

## 七、读者水平校准

根据用户提问的用词与专业度判断其背景：

| 水平 | 写法 |
| ---- | ---- |
| 专家 | 直接使用精确的领域术语，不解释 |
| 进阶 | 术语照用，附简短行内注释 |
| 大众 | 术语首次出现时给出定义 |

## 八、篇幅校准

| 请求类型 | 参考篇幅 |
| -------- | -------- |
| 摘要 / 速览 | 5–10 段 |
| 事实求证 | 5–10 段，直答 + 上下文 |
| 对比 / 排行 | 20–40 段，多用表格 |
| 开放式研究 | 20–40 段，完整分析深度 |
| 明确要求深度（"详尽报告""深挖"） | 不设上限，由主题范围决定 |

## 九、质量门槛（交付前逐项自检）

- [ ] GFM 语法正确，标题层级合理。
- [ ] 对比与结构化数据使用了表格。
- [ ] 事实性论断均有 `[来源:N]` 标注，编号对应真实检索结果。
- [ ] 长报告末尾有完整的"信息来源"清单。
- [ ] 无第一人称表述。
- [ ] 报告脱离对话上下文可独立理解。
- [ ] 篇幅与问题复杂度匹配。
- [ ] 无 TODO、无占位符，所有章节写完。
- [ ] 全部为真实数据，未编造任何引文或数值。
- [ ] 直接回答在对话中，完整分析在报告中。

## 十、红线

1. 禁止编造数据；未核实信息必须打 `[未核实]`。
2. 禁止第一人称与自指表述。
3. 报告必须独立可读。
4. 引用必须来自真实检索结果。
5. 跨对象比较时指标口径、统计周期、单位必须一致。
