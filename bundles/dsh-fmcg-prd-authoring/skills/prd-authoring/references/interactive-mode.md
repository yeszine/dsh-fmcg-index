# 原型优先的交互式 PRD

适用：用户明确要求以可点击原型为评审主体、需求文本与原型联动的场景。交付物为单个自包含 HTML 文件。

## 与常规模式的差别

常规模式中文档是评审主体，原型是辅助说明；原型优先模式中，一个贯穿主流程的可点击原型是评审主体，需求文本通过联动机制为原型提供规则解释。两种模式对产品推理深度的要求相同，只是呈现重心不同。

## 动工前的产品推导

先做产品决策，再画界面：

1. 主要用户与核心任务；
2. 触发点与完成判定；
3. 主路径（从进入到完成）与最重要的恢复路径；
4. 串联流程的业务对象及其状态；
5. 关键页面清单（通常 3–7 屏/态）；
6. 为每个功能分配稳定编号（如 FR-submit），原型与文本两侧共用。

## 页面结构

左右分屏：

- **左侧**：持久化原型，移动端产品置于手机框内，桌面产品置于浏览器框内（不要把桌面产品塞进手机壳）；
- **右侧**：标签页组织的需求文本——概览（必选）、流程与设计说明（按需）、功能详情（必选，承载大部分内容）、共享规则（按需）；
- **顶栏**：标题、版本、模式切换。

另提供"纯文本模式"：把全部需求内容按逻辑顺序拼成可滚动、可打印的长文档；原型页嵌在其对应功能章节的首次出现处。

## 联动机制

- 原型元素与需求章节使用同一稳定编号互相锚定；
- 点击原型中的联动元素：右侧切换到功能详情标签，滚动到对应章节并给出高亮；
- 点击需求章节：对应原型区域尽量同步高亮；
- 编号在需求侧唯一；一个原型页可含多个联动点；
- 启动页、加载页等过渡画面可以不参与联动。

## 原型的行为要求

- 覆盖 P0 主流程与关键恢复路径所需的全部页面和状态；
- 使用真实的业务文案与示例数据，禁用 Lorem ipsum 与空壳占位卡片；
- 操作后界面状态真实变化，禁用 alert 充当产品反馈；
- 校验失败保留已填内容；支持返回、取消、重置等可逆探索；
- 界面上看得见的可点元素必须有响应；范围外入口给出明确的"不可用"反馈；
- 页面、选中对象、表单值、状态、权限等用一套统一的状态模型管理；
- 至少展示一种有代表性的空态、失败态或被阻止态（如与需求相关）。

## 技术要求

- 单文件交付，CSS 与 JS 全部内联，不依赖 CDN、构建工具、接口或本地服务；
- 语义化控件、键盘可达、对比度充足、焦点状态可见；
- 正文字号不小于 14px；窄屏下降级为连贯的单列布局；打印样式隐藏交互控件。

## 内容红线

出现以下情况应返工：

- 只有页面清单，没有行为与规则；
- 把用户的功能列表换个说法复述一遍就当需求；
- 只写顺利路径，回避失败与恢复；
- 为界面控件编造业务规则、限额、指标；
- 惯性加入登录、设置、通知、看板等"万能页面"；
- 在 PRD 中写入数据库、接口、框架等实现层决策；
- 原型与文本两侧的状态、权限、文案口径不一致。
