# 常规 PRD 模板大纲

本文件是常规文档模式的章节骨架与写作提示。按需求规模裁剪：小迭代只保留核心章节，新产品或高风险流程使用完整结构。

## 规模与深度对照

| 需求规模 | 建议深度 | 章节取舍 |
|---|---|---|
| 小迭代 / 单点优化 | 轻量 | 背景简述 + 变更行为与受影响规则写全 |
| 新模块 | 标准 | 背景、目标、范围、用户故事、功能规格、异常 |
| 新产品 / 主流程重构 | 完整 | 全部章节；多角色时补角色-对象-状态模型 |
| 涉及资金 / 合规 / 不可逆操作 | 风险加档 | 无论规模大小，补齐权限、审计、确认、撤销、异常细节 |

篇幅不是质量目标：小需求几节即可完整，复杂流程需要充分细节。章节齐全但内容空洞，不如章节精简但行为明确。

## 章节骨架

### 0. 文档信息
标题、版本、作者、评审状态、关联材料来源。

### 1. 背景与问题
- 观察到的现象（有数据、有出处者优先）；
- 受影响的用户与发生时刻；
- 不做这件事的代价。

### 2. 目标
- 定性结果（默认）：用可观察的行为描述"做到什么算成"；
- 定量目标（有基线时才写）：指标名、当前值、目标值、统计口径。

### 3. 范围
- P0：主流程必需 + 关键失败恢复；
- P1：主流程成立后的重要支撑；
- 明确排除：列出"容易被误以为包含"的条目。

### 4. 用户故事
> 作为【角色】，在【场景】下，我希望【动作】，以便【结果】。

用 US-01、US-02 编号，与功能规格（FR-xx）互相引用。

### 5. 功能规格
按模块分节，每节按需覆盖：

1. 用途与价值；
2. 入口与触发条件（谁、在什么前置条件下能发起）；
3. 处理规则（校验、计算、排序、依赖）；
4. 结果与状态变化（持久化了什么、用户看到什么、通知了谁）；
5. 字段表（必填、类型、取值范围、默认值、可编辑性）；
6. 状态流转（允许的路径与禁止的操作）；
7. 权限（可见性、可操作性、数据边界）；
8. 异常（为空、冲突、超时、取消、重试、恢复）。

### 6. 边界与异常汇总
跨模块的通用异常约定集中书写：网络失败、并发冲突、重复提交、权限失效、数据被占用等。

### 7. 共享规则
权限矩阵、对象生命周期、计算与舍入、通知时机与对象、审计要求。

### 8. 指标（可选）
埋点事件、触发点、统计口径、观察方向。

### 9. 排期（可选）
里程碑与依赖关系；人力与工期没有依据时标注 `【待定】`。

### 10. 待办问题
只放实质影响产品决策的未决项，每条注明当前采用的默认假设。

## 图示建议（静态文档）

- 流程分支 → 流程图；
- 生命周期 → 状态流转表；
- 布局影响需求理解 → 简单线框。

图示服务于需求表达；纯规则、纯计算、后台行为用表格或文字即可，不必强行为其配图。
