# 异常识别与风险分级

对应能力项：**异常检测、风险分级、问题定位**

## 要回答的问题

哪些数字偏离了正常轨道？是录入错误、季节常态，还是真出了经营问题？把问题按严重程度排个序，让管理层先看最要命的。

## 检测手段

| 手段 | 对象 | 做法 |
|---|---|---|
| 波动带检测 | 核心指标 | 历史均值 ± 2~3 倍标准差，或 IQR 区间，出界即标记 |
| 突变扫描 | 同环比 | 单月变动幅度超过阈值（默认 ±20%，可按品类调整） |
| 数据质量核查 | 原始字段 | 空值、重复单据、负数金额、异常大单的占比 |
| 业务红线 | 有明确规则的项 | 如"单客户月退货率 > 5%""费用率超预算 2pp" |
| 趋势偏离 | 对照预期 | 实际值与移动平均 / 预测通道的偏离度 |

## 风险三级分类

| 级别 | 含义 | 经销商场景举例 |
|---|---|---|
| 紧急 | 直接影响当月盈亏或现金流 | 单月转亏、主力品类出货腰斩、大客户停单、任务达成不足四成 |
| 关注 | 偏离常态但尚有解释空间 | 费用率连续上行、某片区连续两月下滑、退货率抬升 |
| 记录 | 小幅波动，留档即可 | 个别 SKU 动销波动、季节性正常回落 |

## 执行步骤

1. 建基线：用近 6–12 个月数据给核心指标算出正常波动区间
2. 逐项扫描：当期值出界即进入候选清单
3. 对上下文：用已知经营事件（大促、春节、客户合同调整、厂家涨价）解释候选项，解释得通的降级
4. 定级：按三级标准打标签
5. 写假设：紧急级必须给出可能原因的假设与核实方式，明确交给谁去查

## 问题清单书写模板

```
问题 N [紧急/关注/记录]：一句话讲清现象（含时间、对象、幅度、绝对额）
  · 基线对比：正常波动范围是多少，这次偏出多少
  · 可能原因：列 1–3 个假设，未经核实的标"（待核实）"
  · 影响测算：对月度任务 / 毛利 / 现金流的量化拖累
  · 核实路径：找谁、查什么单据、什么时候要答案
```

示例：

```
问题 1 [紧急]：8 月 B 片区出货环比 -38%（-95 万）
  · 基线对比：该片区历史月波动在 ±10% 以内
  · 可能原因：连锁客户丙合同到期未续 / 业务员离职交接断档（待核实）
  · 影响测算：拖累全公司当月任务达成 5.2pp
  · 核实路径：本周内由销售经理核对客户丙的订单状态与续约进展
```

## 判断纪律

- 只负责"标异常 + 提假设"，不替业务下"谁对谁错"的结论
- 数据质量问题与真实经营异常分两张清单，别让录入错误干扰经营判断
- 紧急级控制在 5 条以内，超出按影响测算排序截取
- 每条标记都要能说清"为什么这条不正常"，说不清的不要标
- 历史数据不足 3 个月时基线不可靠，整条降级并注明
- 出货与实销背离本身就是一种异常：出货正常但终端动销骤降，按"关注"以上级别处理
